Open Companion Listener v0.1.3 is the **first public release**: a free, open-source Windows remote-control listener with Bitfocus Companion integration.

The native Go listener and CommonJS Companion module run locally. Normal operation requires no subscription, cloud account, Python runtime or license activation. Project code and project-generated artwork are MIT licensed; Go redistribution notices are included.

## Features

- Keyboard shortcuts, single keys, press/hold/release and dedicated Num Lock controls.
- Mouse buttons, relative movement and vertical/horizontal scrolling with 1–20-notch controls.
- Open applications, files, folders and websites; Windows Settings and Control Panel selectors.
- 38 optional drag-and-drop Companion presets.
- Silent tray startup with Open GUI, Restart Listener and Exit; optional per-user sign-in startup.
- HMAC-SHA256 authentication, timestamps, nonce replay checks and trusted Companion peer IP.

The release includes the completed dashboard authority, transactional settings, replay-lifecycle, Companion migration and bounded HTTP transport corrections. Publication preparation introduces no application behavior changes.

## Windows installation

1. Verify the Windows ZIP and extract it to a permanent folder. Run `OpenCompanionListener.exe` as your normal Windows user.
2. Find the notification-area icon, then double-click it or choose **Open GUI**. The local dashboard is `http://127.0.0.1:17993/`; it does not open automatically.
3. Configure the listen address, trusted Companion host IP and API port (default `17992`). Copy the private pairing key into the Companion connection.
4. Restrict inbound TCP 17992 in Windows Firewall to that specific trusted host on your private network. Never port-forward the API or dashboard to the Internet.
5. Optionally enable **Start with Windows** after placing the EXE in its permanent location. This is per-user sign-in startup, not a Windows service.

## Companion installation

1. Verify and extract the module ZIP to a staging directory. Use Companion 4.1+ with API 1.13/node22 support and Node 22.8+ within the 22.x line.
2. In `companion-module-community-openlistener`, run each command and stop on failure:

   ```text
   npm ci --omit=dev --ignore-scripts --no-audit --no-fund
   npm run validate
   npm test
   ```

3. Copy that prepared folder into the developer/extra module **parent** directory configured in Companion. This ZIP is not an in-app upload package. Installation requires npm registry access; normal operation remains local.
4. Restart Companion when safe. Add the **Open Companion Listener** connection using the Windows PC's IP, port and pairing key. Add presets only if desired.

For existing installations, export the Companion configuration and back up the old module before upgrading. Restore both the module and matching configuration export for rollback. See the [installation and rollback guide](https://github.com/ninoleto/OpenCompanionListener/blob/v0.1.3/docs/COMPANION-INSTALL.md).

## Verification and known limitations

- Automated Windows Go race tests and both vet modes passed. The module's 28 tests and installed-base manifest validation passed; npm audit reported zero advisories.
- The corrected EXE passed an isolated smoke test covering startup, dashboard guards, signed status, replay rejection after save/restart, duplicate-instance exit, key rotation and shutdown. Microsoft Defender completed a scan reporting no threats (exit 0). Neither result guarantees safety or universal compatibility.
- The owner reports working Num Lock, keyboard/mouse controls, DisplaySwitch.exe arguments 1–4, AutoHotkey launching, Voicemeeter recorder/VBAN feedback workflows, and corrected module installation on ZORIN with 28 passing tests. These are scoped owner observations; detailed historical test-time binary attribution has not been independently established.
- Windows 10/11 x64 is the desktop target. Linux desktop input is not implemented; Companion may run on a separate supported host. Not every feature or Windows configuration has been tested. Detailed tray/startup, all-preset, interruption and real-host migration/rollback coverage remains incomplete.
- The EXE is unsigned. Windows focus, integrity, lock-screen and session boundaries apply. OS acceptance does not mean a launched task has finished.
- HTTP requests are authenticated, **not encrypted**. Pairing grants desktop-user execution authority, including executable arguments and interpreters. Use a trusted LAN/private overlay and firewall restrictions; do not run the listener as Administrator.
- Replay state survives settings saves and in-process restarts but is memory-only across full process exits. If an old module already destroyed an expression during migration, recover it from a pre-upgrade configuration export.
