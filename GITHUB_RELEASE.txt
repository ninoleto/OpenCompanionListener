# Open Companion Listener v0.1.4

Open Companion Listener receives commands from Bitfocus Companion and sends
keystrokes, shortcuts, mouse clicks, movement and scrolling to a Windows PC.
It can also open applications, files, URLs and scripts through an installed
interpreter or file association. It is free and open source under the MIT license.

## What changed

The Companion module is now a bundled TGZ installed through **Modules → Import
module package**. Ordinary users need no separate Node.js, npm or developer
folder. Installation and upgrade instructions are separate from developer docs.
The signed protocol, connection/action IDs, 38 optional presets and migrations
remain compatible. Existing connections and buttons should be retained.

The Windows executable, tray and dashboard use the supplied owner-approved logo.
The dashboard retains its existing layout and colors. The verified Companion
TGZ is preserved byte-for-byte during final packaging.

The owner confirms successful GUI import on the production Companion host,
retained settings, a working connection and most existing buttons working.
The owner also confirms live Windows testing PASS for the EXE, tray, dashboard
and existing Companion buttons. Detailed all-preset and OS-matrix coverage is
not claimed.

These are the unchanged verified artifacts built from source commit
`30be74c8841594d67a4aaf49ee5cc4f6db36c827`, tagged `v0.1.4`. Their embedded
build-time metadata remains unchanged; current validation is recorded in the
[release verification](https://github.com/ninoleto/OpenCompanionListener/blob/main/docs/VALIDATION-v0.1.4.md).

## Installation

1. On Windows 10/11 x64, extract the Windows ZIP into a permanent folder and run
   `OpenCompanionListener.exe` as your normal user. It starts silently in the tray.
2. Choose **Open GUI** from the tray, then configure the listen IP, trusted
   Companion IP and API port (default `17992`). Keep the pairing key private.
3. In Companion 4.1+ with the node22 runtime, open **Modules → Import module
   package** on the Companion host and select the compressed TGZ.
4. Add an **Open Companion Listener** connection, enter the Windows IP, API port
   and pairing key, and check that it connects. When upgrading, export your
   configuration first and select the new version for the existing connection.
5. Configure actions or drag optional presets onto your pages. Input goes to
   the focused Windows application.

For old development-folder installations, follow the
[transition and rollback guide](https://github.com/ninoleto/OpenCompanionListener/blob/main/docs/COMPANION-INSTALL.md).
Keep a local copy of the old module and its matching configuration backup.

## Security and limits

Commands are authenticated with HMAC-SHA256 but are not encrypted. Use a trusted
LAN/private overlay and restrict the API firewall rule to the Companion host.
Never expose API or dashboard ports to the Internet. Pairing grants desktop-user
authority, including launching code. Do not run the listener as Administrator.

The EXE is unsigned. Windows focus, UAC and session restrictions apply.
An “OS accepted” response does not prove that a launched task finished.
See [security](https://github.com/ninoleto/OpenCompanionListener/blob/v0.1.4/SECURITY.md)
and [verification scope](https://github.com/ninoleto/OpenCompanionListener/blob/main/docs/VALIDATION-v0.1.4.md).

[Developer instructions](https://github.com/ninoleto/OpenCompanionListener/blob/v0.1.4/docs/DEVELOPMENT.md)
cover builds and contributions. Report sanitized versions and reproduction steps
in [GitHub Issues](https://github.com/ninoleto/OpenCompanionListener/issues);
never include pairing keys or private settings.
